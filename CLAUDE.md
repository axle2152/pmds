# PMDS project notes

Notes for AI coding assistants and contributors working in this repository.

PMDS (Phase Modulation Data Service, working name) carries RDS-style station data (PI, PS,
RadioText, PTY, alert flag, extended fields) as slow phase modulation of a mono AM carrier:
93.75 bit/s, 8.6 degrees peak deviation, envelope untouched. Maintainer: Michael Foley,
KK4EKN (GitHub axle2152). Experimental; draft spec, not a standard.

## Where things are

- `docs/PMDS_Draft_Specification_version_0.2.md`: the spec. Where spec and code disagree, the
  spec is the intent and the code is the bug. Keep its Appendix A test vectors, section 11
  numbers and revision history in step with code changes. Equations use ```math blocks.
  It is the only copy: no Word or PDF versions in the repository. A PDF, when one is
  needed, is made from this file (GitHub's page printed to PDF does it).
- `docs/PMDS_Receiver_Design_Notes.md`: informative notes on building a PMDS-capable AM radio
  (radio types, decoder needs, what spoils the phase). Keep claims sourced or marked untested.
- `pmds/`: the core package (encoder, demod, framer, codec, sources). Plain Python + numpy,
  **Apache 2.0**. It must never import GNU Radio or copy from the GPL files.
- Top-level `pmds_*.py`, `skywave_channel.py`, `am_data_tx.grc`: GNU Radio blocks, the tuner
  add-on, monitor, bench tools. **GPL 3.0 or later** (`COPYING`). They sit beside `pmds/` on
  purpose: they find each other and the package through their own folder. Don't move them
  into a subfolder.
- The tuner is axle2152/all-mode-receiver. PMDS plugs into its AM receiver as an add-on:
  `pmds_addon.py` (the decoder blocks, the 1 Hz carrier PLL data path, what the tuner shows)
  and `pmds_monitor.py` (key I), registered through the `all_mode_receiver.addons` entry point
  in `pyproject.toml` (and in `setup.py` for old setuptools). The interface is
  all-mode-receiver's `docs/ADDONS.md`. Nothing about PMDS goes into that repository but the
  generic interface; this repository keeps no copies of its tuner or receivers.
- `pmds_check.py` and `pmds_channel_test.py` take the decoder and data path from
  `pmds_addon.py`, so the bench tools decode exactly as the tuner does.
- `tests/test_pmds.py`: self-test, no GNU Radio needed.
- `c/`: the decoder ported to plain C99 for microcontrollers (compact framing, 93.75 bit/s
  only), **Apache 2.0**, no GNU Radio code (its carrier PLL and filters were written fresh).
  It must give exactly the same bits as `pmds/demod.py` and `pmds/framer.py`:
  `tests/test_c.py` checks that, so a change to the Python decoder needs the same change
  in C. `c/make_test_iq.py` makes I/Q WAV test recordings (44.1 kHz, carrier at +12 kHz).
- `firmware/teensy_rx/`: the prototype radio's Teensy 4.1 sketch, Apache 2.0. Its
  `src/pmds/` is a copy of `c/`; edit `c/`, then `python c/sync_firmware.py`
  (`tests/test_pmds.py` fails on a stale copy). The prototype plan is in `firmware/README.md`,
  the step 3 schematic and wiring in `firmware/FRONT_END.md` (sheets drawn by
  `firmware/hardware/draw_schematic.py` with schemdraw, checked in ngspice by
  `firmware/hardware/simulate.py`), and the parts list in `firmware/PARTS.md`: Teensy 4.1 +
  Audio Adaptor, a quadrature sampling mixer (74HC4052, 74HCT74, MCP6022) with an Si5351, low
  IF 12 kHz, all powered from USB. Keep high-current supplies off the breadboard.
- `am_data_tx.py` and `am_data_tx_epy_block_*.py` are generated by GNU Radio Companion from
  the `.grc` (the embedded block code lives inside the `.grc`); they're git-ignored.
- Branch `experimental-qpsk`: physical-layer variants (first, QPSK at 187.5 bit/s), with
  results in its `docs/QPSK_Experiment.md`. Main stays as it is unless a variant wins.

## Install and test

    pip install -e .              # from this top folder, not pmds/; also installs the add-on
    python tests/test_pmds.py     # must pass before every commit
    python tests/test_c.py        # needs a C compiler; run it when the decoder or c/ changes
    python tests/test_addon.py    # GNU Radio + all-mode-receiver beside this folder; run it when
                                  # pmds_addon.py, the decoder or the tuner's AM receiver changes
    python pmds_channel_test.py   # needs GNU Radio; --program bass, --alert, --presets, --dev, --co
    python tests/false_displays.py   # long: false alerts and wrong stations in simulated fading

`setup.py` is a fallback for old setuptools (Ubuntu 22.04); version comes from
`pyproject.toml`. When bumping the version, change `pyproject.toml`, `pmds/__init__.py`
and `CITATION.cff` (`version`, `date-released`) together.

Releases: a GitHub release tagged `vX.Y.Z` on main is archived by Zenodo, which reads
`.zenodo.json` (title, description, creators, keywords, licence "other-open" with the three
real licences in the description) and ignores `CITATION.cff` while that file exists; its
CITATION.cff reader takes only one licence, and ours lists three for GitHub's citation box.

## Working conventions

- Supported setups: Windows with radioconda (or MSYS2), and Ubuntu 22.04 with an editable
  user install, `pip install --user --no-build-isolation -e .` (no sudo). Without
  `--no-build-isolation`, Ubuntu 22.04's pip 22.0.2 runs `setup.py develop` with the user site
  off and fails with "Permission denied" on /usr/local; patching setup.py only hits further
  setuptools 59 bugs. Both setups update with `git pull`.
- Give git steps as exact commands, one per code block.
- Changes go in through pull requests. After a merge, give the update commands for both
  setups, and the `pip install -e` again when `pyproject.toml` or the add-on changed.
- Test hardware, not reachable from a cloud session: a HackRF One transmitter, RTL-SDR
  receivers, a Sangean HDR-16 (synchronous detector) and a C.Crane CC Pocket. Bench and
  listening results come from them. The Soapy HackRF sink runs only whole-MHz rates (2 to
  20 Msps), and a flowgraph's rate variables must match it (`am_data_tx.grc` sends at exactly
  2 Msps). The HackRF tunes `tx_offset` (default 100 kHz) above the carrier (`carrier_freq`)
  and a rotator after the resampler moves the signal back down, so the HackRF's own I/Q image
  and LO leakage land clear of the station; with the carrier on its centre (0, the old way)
  they land on it, and in simulation an image 15 dB down turned 8.6 degrees into 5.9 (the
  bench read 6.8 as about 4.8). The bench result with the offset is still to come (then spec
  sections 10 and 12). The RTL-SDR clips often on medium wave.
- The README is written in plain language for a general reader; keep that tone.

## Aims and design decisions

- Free or very cheap for anyone to use: no patent or licence fee (PMDS builds on prior art
  and existing standards, and a fee would be a reason for stations and makers not to bother).
  A patent and prior-art search in November 2026 found no live US patent claiming the
  physical layer or framing; the prior art is in spec section 2. The specification is under
  CC BY 4.0 (its header and the README's licence table); a trademark for the name is an open
  item (spec section 12). Possible next steps:
  review by broadcast engineers, an industry body (NRSC), and the FCC rules (47 CFR 73.127).
- 93.75 bit/s at 8.6 degrees is the sweet spot: more rate or deviation means more audibility
  and data energy further from the carrier. 46.875 and 23.4375 bit/s are too slow; they stay
  in the decoder for bench comparisons only, and 23.4375 can pass for the C-QUAM pilot in a
  simple pilot detector (spec section 10). Main stays BPSK at 93.75 bit/s and 8.6 degrees:
  simple wins (November 2026). Faster or quieter variants are tested only on an experimental
  branch.
- PMDS doesn't hold the tuner in mono: the tuner's own pilot test decides stereo, and a pilot it
  hears always wins, because PMDS falsely syncs now and then on real C-QUAM stations (their L−R
  is on the same phase; bass panned to one side fills PMDS's band).
- One station at a time: with several PMDS stations on a channel at night, only the data of
  the station on show may be displayed. Core and extended groups carry the PI; RadioText
  counts only next to a core group of that station; a PI needs two core groups in a row and
  an alert two groups in a row, one of them a core group (spec sections 8 and 9).
  `pmds_channel_test.py --co` puts a second station on the channel. The ISRC field was
  dropped in November 2026.
- Signed alerts: left out for now (November 2026): who would hold the master key, how stolen
  keys are cancelled, and who pays were all open. Room is kept (receivers ignore reserved
  bits and extended types 4 to 15); the principles for a later version are in spec section 12.
  The ATSC 3.0 signing fees are the example of what to avoid.
- The encoder needs a sample rate that is a whole multiple of the bit rate (192 kHz in the
  flowgraph); the library refuses others, the GNU Radio block warns.
- HD Radio hybrid stations are ruled out (tested November 2026, spec section 10 and its
  figure `docs/pmds_hd_hybrid_spectrum.png`): PMDS's energy falls in the receiver slot of the
  HD reference carriers at ±182 Hz, no bit rate gets out of the way, and fewer than 100 AM
  stations still run hybrid HD. HD Radio (NRSC-5) is proprietary and licensed: keep NRSC-5
  flowgraphs, gr-nrsc5 code and HD signal simulators out of this repository.

## Ideas for their own chats (not started)

- C-QUAM stereo alongside PMDS: after demodulating the phase, split by frequency. L−R would
  have to be cleared below about 250 Hz at the transmitter; in the receiver, phase content
  above about 200 Hz is L−R and below goes to the PMDS decoder.
  A proof of concept only: existing C-QUAM radios would still play the data as L−R.
- Physical-layer variants, on an experimental branch, never main until they win: two
  orthogonal streams (QPSK-like) for 187.5 bit/s, or part of that gain spent on a lower
  deviation (two streams should also turn the synchronous detectors' steady 187.5 Hz tone into
  noise); stronger soft-decision coding. Each one is a switchable option, compared with today's
  BPSK on the same simulator presets, false-display runs, co-channel test and audibility
  measures (sync-detector tone, energy above 150 Hz), then by ear on the bench. A changed
  physical layer needs its own prior-art check. For reference, AMSS (EBU Technical Review,
  January 2006): biphase, root-raised-cosine shaped, ±20 degrees, 46.875 bit/s (256 samples at
  DRM's 12 kHz), 47-bit blocks of 36 data and 11 CRC bits taken from the German AMDS.

## Testing in a cloud session

- GNU Radio: `apt-get update`, then `apt-get install -y --no-install-recommends gnuradio
  gr-osmosdr` (Ubuntu 24.04, GNU Radio 3.10.9). Its Python modules are built for the system
  Python 3.12: run the GNU Radio tools with `/usr/bin/python3.12` when plain `python3` is a
  newer one. Python blocks inside a hier block must stay referenced from Python, or the
  flowgraph segfaults on start.
- `tests/test_addon.py` needs all-mode-receiver: clone axle2152/all-mode-receiver beside this
  folder (it looks for `../all-mode-receiver`), or pass `--radio`.
- Ubuntu 22.04's GNU Radio 3.10.1 reaches `hier_block2`'s own methods (`to_basic_block`,
  `connect`) through `__getattr__`: a stand-in block with a catch-all `__getattr__` must ask
  `self._impl` first, or the receiver fails to connect it. all-mode-receiver's CLAUDE.md says
  how to run GNU Radio 3.10.1 in a 22.04 chroot.
- `am_data_tx.grc` holds a copy of `pmds_encoder.py` and `skywave_channel.py` as embedded
  blocks. Change the file and the copy together; loading the `.grc` with PyYAML and comparing
  `_source_code` with the file shows whether they still match.
- The Teensy toolchain (arduino-cli and the Teensy core) can't be downloaded in the cloud
  session. To check C code for the Teensy's processor: `apt-get install -y
  --no-install-recommends gcc-arm-none-eabi libnewlib-arm-none-eabi`, then
  `arm-none-eabi-gcc -mcpu=cortex-m7 -mfloat-abi=hard -mfpu=fpv5-d16 -mthumb -c`. The sketch
  itself can be built on the PC against small stand-ins for Arduino's SD and Serial classes;
  its first real build is in the Arduino IDE with Teensyduino.
- To check the install route: `pip install -e .` in a venv, then all-mode-receiver's
  `radio.addons.classes_for('AM')` should list PMDS. A venv or root misses the Ubuntu 22.04
  `--user` case: for that, `debootstrap --variant=minbase --components=main,universe
  --include=python3-pip,python3-numpy jammy <dir>` (script `gutsy`), then install as an
  ordinary user in the chroot.
