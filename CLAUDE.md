# PMDS project notes

PMDS (Phase Modulation Data Service, working name) carries RDS-style station data (PI, PS,
RadioText, PTY, alert flag, extended fields) as slow phase modulation of a mono AM carrier:
93.75 bit/s, 8.6 degrees peak deviation, envelope untouched. Owner: Michael Foley, KK4EKN
(GitHub axle2152). Experimental; draft spec, not a standard.

## Where things are

- `docs/PMDS_Draft_Specification_version_0.2.md`: the spec. Where spec and code disagree, the
  spec is the intent and the code is the bug. Keep its Appendix A test vectors, section 11
  numbers and revision history in step with code changes. Equations use ```math blocks.
  It is the only copy: no Word or PDF versions in the repository. A PDF, when one is
  needed, is made from this file (GitHub's page printed to PDF does it).
- `docs/PMDS_Receiver_Design_Notes.md`: informative notes on building a PMDS-capable AM radio
  (radio types, decoder needs, what spoils the phase). Keep claims sourced or marked untested.
- `pmds/`: the core package (encoder, demod, framer, codec, sources). Plain Python + numpy,
  **Apache 2.0**. It must never import GNU Radio or copy from the GPL files.
- Top-level `pmds_*.py`, `skywave_channel.py`, `am_data_tx.grc`: GNU Radio blocks, the tuner
  add-on, monitor, bench tools. **GPL 3.0 or later** (`COPYING`). They sit beside `pmds/` on
  purpose: they find each other and the package through their own folder. Don't move them
  into a subfolder.
- The tuner is axle2152/all-mode-receiver (public). PMDS plugs into its AM receiver as an
  add-on: `pmds_addon.py` (the decoder blocks, the 1 Hz carrier PLL data path, what the tuner
  shows) and `pmds_monitor.py` (key I), registered through the `all_mode_receiver.addons`
  entry point in `pyproject.toml` (and in `setup.py` for old setuptools). The interface is
  all-mode-receiver's `docs/ADDONS.md`. Nothing about PMDS goes into that public repository
  but the generic interface; this repository keeps no copies of its tuner or receivers.
- `pmds_check.py` and `pmds_channel_test.py` take the decoder and data path from
  `pmds_addon.py`, so the bench tools decode exactly as the tuner does.
- `tests/test_pmds.py`: self-test, no GNU Radio needed.
- `am_data_tx.py` and `am_data_tx_epy_block_*.py` are generated by GNU Radio Companion from
  the `.grc` (the embedded block code lives inside the `.grc`); they're git-ignored.

## Install and test

    pip install -e .              # from this top folder, not pmds/; also installs the add-on
    python tests/test_pmds.py     # must pass before every commit
    python tests/test_addon.py    # GNU Radio + all-mode-receiver beside this folder; run it when
                                  # pmds_addon.py, the decoder or the tuner's AM receiver changes
    python pmds_channel_test.py   # needs GNU Radio; --program bass, --alert, --presets, --dev

`setup.py` is a fallback for old setuptools (Ubuntu 22.04); version comes from
`pyproject.toml`. When bumping the version, change `pyproject.toml` and
`pmds/__init__.py` together.

## How the owner works

- New to git and GitHub. Explain git steps plainly and give exact commands.
- Machines: Windows (radioconda / MSYS2) and a Linux laptop (Ubuntu, editable install with
  `pip install --user -e .`, no sudo). Both update with `git pull`.

  receivers, Sangean HDR-16 (synchronous detector), C.Crane CC Pocket. Bench and listening
  results come from them. The Soapy HackRF sink runs only whole-MHz rates (2 to 20 Msps), and
  a flowgraph's rate variables must match it (`am_data_tx.grc` sends at exactly 2 Msps). Its
  carrier sits on the HackRF's own centre frequency; offset tuning is still to be tried (spec
  section 10). The RTL-SDR clips often on medium wave.

  zip arrives, merge it into this layout and keep the install fixes, `.gitignore` and README
  setup section rather than overwriting them.

- Merges pull requests on GitHub. After each merge, give the update commands for both machines,

## The owner's aims for PMDS

- Give it the best chance at a real life: free or very cheap for anyone to use. No patent or
  licence fee is planned (it builds on prior art and existing standards, and a fee would be a
  reason for stations and makers not to bother). Kept private until the owner has shown it to a
  few people; an attorney friend (also a ham) may review it, but no review has happened yet. A
  patent and prior-art search in November 2026 found no live US patent claiming the physical
  layer or framing; the prior art is in spec section 2. A US wordmark search found the name
  free (one dead PMDS registration); a trademark, and the licences for the spec and the logos
  (AI-generated, so the owner may redraw them), are on the attorney's list (spec section 12).
  Next steps the owner has in mind:
  opinions from others (SBE Chapter 5), then perhaps an industry body (NRSC) and the FCC rules
  (47 CFR 73.127).
- 93.75 bit/s at 8.6 degrees is the sweet spot: more rate or deviation means more audibility
  and data energy further from the carrier. 46.875 and 23.4375 bit/s are too slow; they stay
  in the decoder for bench comparisons only, and 23.4375 passes for the C-QUAM pilot (spec
  section 10).

## Ideas for their own chats (not started)

- C-QUAM stereo alongside PMDS: after demodulating the phase, split by frequency. L−R would
  have to be cleared below about 250 Hz at the transmitter; in the receiver, phase content
  above about 200 Hz is L−R and below goes to the PMDS decoder.
- HD Radio (NRSC-5) hybrid on AM with PMDS (spec section 12: test it or keep it out of scope).
  The owner has IP and licensing concerns about HD Radio itself.

  `radio.addons.classes_for('AM')` should list PMDS.
